# M0 contract-freeze gate

## Purpose

M0 freezes the implementation principles and authorizes M1, M2, M3, and M5
foundations without claiming production HTTP, JSX, HTMX, security, performance,
or release behavior. The gate is governed by the [release-gate
standard](../../engineering/release-gates.md) and the [GH-010 issue](../../issues/m0/gh-010-run-and-record-the-m0-contract-freeze-gate.md).

## Gate command battery

The canonical `bun run ci:m0` command runs 17 ordered, fail-closed steps:

1. Bun preflight;
2. formatting, lint, and strict typecheck;
3. OKF validation, link validation, dependency graph, and governance checks;
4. architecture tests and boundary scan;
5. benchmark smoke and parity;
6. stable and experimental browser lanes plus combined report; and
7. the complete test suite and workspace build.

The command stops on the first nonzero child status. Browser, fixture, Playwright,
report, and benchmark prerequisites are mandatory. The deliberate GH-008
incorrect-header command exits nonzero inside each lane as expected negative
evidence; the lane wrappers and aggregate gate exit zero only when that negative
assertion is observed.

## Accepted deviations and residual risks

- GH-004 clears a temporary implementation name/namespace decision, not legal
  clearance. Nothing is reserved; official trademark screening, counsel review,
social-handle checks, registrar proof, and publication reservation remain future
  release-gate work, including GH-086. No announcement or package publication is
  authorized by M0.
- GH-005 freezes principles, ownership, dependency direction, and trust
  boundaries. Exact public signatures remain deferred until implementation
  evidence, and the boundary checker is a source-text/import-graph layer rather
  than a semantic compiler.
- GH-006 validates the configured Linux environment; hosted cross-platform CI
  evidence is not implied.
- GH-007 measures raw Bun/Hono in-process scenarios only. Bundar timing is
  explicitly deferred, no speed claim or threshold is accepted, and startup,
  network, and slow-client workloads remain future M1/M2 evidence.
- GH-008 proves the pinned browser fixture lanes only. htmx 4 beta is experimental,
  not GA; its lifecycle result differs from htmx 2, and streaming/partial
  transport plus Bundar runtime conformance remain future M3 work.
- The browser-dependent gate is not added to ordinary GitHub CI because the
  Playwright CLI/browser asset is not yet packaged as a reproducible repository
  dependency. Local execution is mandatory for this gate and its transcript.
