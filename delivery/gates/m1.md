# M1 HTTP-core gate

## Purpose

M1 closes with maintainers accepting the Bun-native HTTP core — route
compilation to `Bun.serve` native route tables, per-request context,
startup-composed middleware, the error boundary, response helpers, terminal
behavior, and the contract matrix — as the stable foundation for the JSX and
HTMX layers. The gate is governed by the [release-gate
standard](../../engineering/release-gates.md) and the [GH-025
issue](../../issues/m1/gh-025-run-and-record-the-m1-http-core-gate.md). No JSX
or HTMX release claim is made here (out of scope); the performance half of
this record is the [M1 performance and resource
gate](m1-performance.md) (GH-024).

## Gate command battery

The canonical `bun run ci:m1` command runs 28 ordered, fail-closed steps (a
strict superset of `ci:m0`): preflight; format, lint, and strict typecheck;
type-level tests; OKF validation, links, issue graph, and governance checks;
architecture unit tests plus the static package-boundary check; benchmark

raw-HTML security audit; both browser lanes and their report; the full test
suite; and the build. The exact 28 exit-0 lines are in the transcript.

## Reviewed deviations from M0 contracts

1. **`@bundar/cli` depends on `@bundar/core`** (`workspace:*`). M0 froze
   zero-runtime-dependency rules for `@bundar/core` and `@bundar/jsx` (still
   enforced per-package by `pack:inspect` and the architecture check). The
   CLI consuming the workspace core it scaffolds for was introduced and
   approved in GH-070; no other package gained a runtime dependency.
2. **Benchmark report schema moved 1 → 2** (GH-024): the Bundar adapter is
   now measured and startup/RSS probes were added. Internal artifact
   contract, not a public API.
3. **New tooling scripts** (`ci:m1`, `api:check`, `bench:m1`, `bench:report`,
   `routes:check` and friends from their own issues): additions only; no M0
   script was removed or weakened.

No public API exception exists in M1: no ADR or migration note is required.
The accepted public surface at this gate is 61 runtime exports from
`@bundar/core` (snapshot [`artifacts/api/core.md`](../../artifacts/api/core.md),
byte-checked by `api:check`), plus the `@bundar/jsx` and `@bundar/htmx`
surfaces recorded in their own evidence transcripts.

## Acceptance findings

- **No second router or forbidden package edge exists.** Routing compiles to
  `Bun.serve` native route tables (GH-015); the architecture check (46 source
  files, 7 package rules) and the architecture unit tests pass; JSX→core
  imports remain forbidden and absent; raw HTMX protocol strings remain
  confined to `@bundar/htmx`.
- **All core tests and package inspections pass.** 352/352 tests repository
  wide, including the 13-test M1 contract matrix file (42 tests across the
  core integration directories) and the external type consumers;
  `pack:inspect` passes for core and jsx with zero runtime dependencies.
- **Performance evidence is reviewed.** The committed M1 artifact satisfies
  the reviewed static fast-path tolerance (0.65× raw-bun p50 ≤ 2.0× ceiling
  in the recorded run; the check re-runs inside `ci:m1`); trade-offs and the
  `parseForm` follow-up
  ([#97](https://github.com/ther12k/bundar/issues/97)) are recorded in the
  [performance gate](m1-performance.md).
- **No mandatory test failure is hidden, skipped, or downgraded.** Every
  battery step exits 0 with nothing skipped; the two GH-007 benchmark
  assertions superseded by the real adapter were updated (not deleted) in
  GH-024 and assert the stronger property.

## Authorization

M2 and M3 dependent work is authorized on this foundation: GH-034
(renderToStream) and GH-035 (typed common HTMX attributes) are immediately
unblocked, followed by GH-036–038 (M2 gate chain) and the M3 chain
(GH-045–056). Execution context: dependency-free issues from later milestones
were intentionally completed early in dependency order (GH-026–033 M2 JSX
semantics, GH-039–044 M3 dialect adapters, GH-057 M4 body parsing, GH-070 M5
CLI, GH-073 M5 route manifests); this gate confirms the HTTP-core foundation
under all of them and authorizes the remaining dependent issues. This gate
makes no JSX or HTMX release claim.

## Accepted residual risks

- Single-machine benchmark variance and the in-process native-dispatch
  substitution (disclosed in the performance gate); GH-083 re-runs the suite
  before any public performance statement.
- `request.params` population relies on Bun's documented route-handler
  contract; a Bun major changing that contract is caught by the contract
  matrix, not prevented.
- Production error opacity depends on `NODE_ENV`; the boundary tests pin the
  behavior, and deployment misconfiguration remains an operational risk
  documented in GH-020's transcript.
