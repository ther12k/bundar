# Agent map standard

Local context beats one enormous root instruction file (ADR-0019). Every
application and feature may carry an `AGENTS.md` — a SHORT map that refines,
never restates, the source-of-truth docs.

## Budget and required sections

**Hard limit: 60 lines.** Required sections, in order:

```markdown
# <scope> — agent map

Purpose: <one sentence>.
Public entrypoint: <file or export>. Route/DOM contracts: <ids or route names>.

Allowed imports: <direction summary, e.g. "routes → actions → types; views → read models">.
Read zones: <glob or files>. Write zones: <files this scope's tasks may edit>.

Checks:
- <focused command(s) that must pass>

Escalate when: <conditions requiring a human/decision instead of proceeding>.

Details: ../../engineering/application-structure.md (do not restate it here).
```

## Precedence and anti-duplication

1. Root `AGENTS.md` (if any) sets repo-wide conventions; local maps REFINE.
2. A local map never copies policy text — it links (`engineering/*`) and
   states only deltas ("this slice additionally forbids X").
3. Conflicts resolve outward: framework docs > application map > feature
   map > task metadata.

## Drift checking

`bun run agent-map:check` validates every `AGENTS.md` under scanned apps:

- line budget (≤ 60);
- each path mentioned in backticks that looks like a repo path exists;
- each fenced command's script name exists in some package.json, or its
  first token resolves to a file;
- required section keywords present (`Purpose:`, `Checks:`).
